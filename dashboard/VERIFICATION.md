# تحقق MaYor Cloud Pro MTF

## حالة واجهة اللوحة

تم فتح `dashboard/mayor_dashboard.html` محليًا في Chromium بتاريخ 2026-08-19. ظهرت الواجهة باتجاه عربي RTL ومتوافقة مع شاشة الهاتف، مع بطاقات إجمالي الصفقات ونسبة النجاح وصافي النتيجة والصفقات المفتوحة، ومنحنى الأداء، وملخص الجودة، وتوزيع الأزواج، وجدول السجل.

تم تحميل بيانات العرض التجريبية بنجاح للتحقق من الواجهة فقط. البيانات التجريبية ليست نتيجة تداول ولا تدخل في بوابة التحقق.

## حالة البوابة الإحصائية

آخر تشغيل فعلي باستخدام بيانات Binance العامة:

| الحقل | النتيجة |
|---|---:|
| الرمز | BTCUSDT |
| عدد تبديلات Monte Carlo | 200 |
| طريقة Monte Carlo | Permutation Paths |
| In-Sample trades | 0 |
| Out-of-Sample trades | 0 |
| الحالة | BLOCKED |
| سبب الحجب | العينة أقل من الحد الأدنى ولم تُنتج صفقات كافية للتحقق |

بناءً على ذلك، **البث الحي محجوب عمدًا**. لا يجوز تحويل الحالة إلى `PASS` يدويًا ولا استخدام بيانات تجريبية أو عينة صغيرة لتجاوز البوابة. يجب تشغيل `npm run backtest` على بيانات تاريخية مغلقة كافية، مع تحقيق الحد الأدنى الموثق في `CONFIG.minBacktestTrades` و`CONFIG.minOosTrades`، وإيجابية OOS وProfit Factor أكبر من 1 وZ-score والرتبة المئينية المطلوبة.

ينتج محرك التحقق الملفين:

- `data/backtest_report.json`: التقرير التفصيلي لـ IS/OOS وMonte Carlo والارتباط.
- `data/verification.json`: الحالة المختصرة التي يقرأها `engine/scan.js` قبل السماح بالبث.

## طريقة الاستخدام على الهاتف

اضغط «فتح tracked.json» واختر `data/tracked.json` من مدير الملفات. ويمكن اختيار `data/verification.json` لعرض حالة البوابة. تعمل اللوحة محليًا دون خادم، ولا تحتوي على مفاتيح Telegram أو مفاتيح API.

> النظام بحثي وإشعاري فقط، ولا ينفذ أوامر تداول. لا تمثل نتائج backtest ضمانًا للنتائج المستقبلية، ويجب إبقاء البث محجوبًا حتى تتوفر عينة مستقلة كافية.
